\subsection{Exploratory Script: Reading a Single Node}

Before configuring WinCC OA, you can verify OPC UA connectivity using this simple script that reads the FPGA temperature directly:

\textbf{File:} \texttt{read\_fpga\_temp.py}\\
\textbf{Location:} \texttt{/home/naherlin/}

\begin{lstlisting}[language=Python]
#!/usr/bin/python3
from opcua import Client
import time

OPCUA_URL = "opc.tcp://192.168.0.117:4841"
NODE_ID = "ns=2;s=SRTM.FPGA_temp"
PING_TIME = 10  # seconds

client = Client(OPCUA_URL)
try:
    client.connect()
    node = client.get_node(NODE_ID)
    for i in range(PING_TIME):
        value = node.get_value()
        ts = time.strftime('%Y-%m-%d %H:%M:%S')
        print(f"{ts} | FPGA_temp = {value}")
        time.sleep(1)
except Exception as e:
    print("ERROR:", e)
finally:
    client.disconnect()
\end{lstlisting}

\textbf{Usage:}
\begin{lstlisting}
/usr/bin/python3 read_fpga_temp.py
\end{lstlisting}

\begin{tipbox}
\textbf{Tip:} This script confirms that the OPC UA server is accessible and the node path (\texttt{ns=2;s=SRTM.FPGA\_temp}) is correct before configuring WinCC OA.
\end{tipbox}

\section{Creating a New WinCC OA Project}
%==============================================================================

\subsection{Starting the Project Administrator}

Launch the Project Administrator from terminal:
\begin{lstlisting}
startPA
\end{lstlisting}
This starts the Project Administrator window.

\subsection{Method A: Quick Start}

This is the preferred method because it will short circuit the need to create datapoints and install JCOP.\\

\noindent\textbf{Step 1:} Create a new project from the PA console.
\begin{enumerate}
    \item Click the \textbf{New Project} button (blank document icon in toolbar)
    \item Select \textbf{Distributed project}
    \item Enter a Project Name and use the default path: /home/monitor/WinCC/SRTM\_SandBox/
    \item Change the System name to: ATLLARLASPSRTM
    \item Click \textbf{OK} 
\end{enumerate}

\begin{warningbox}
\textbf{Important:} Use ``Distributed project'' type, NOT ``Standard project''. Standard projects cause errors in later configuration steps. Datapoints will have a \texttt{ATLLARLASPSRTM:} prefix.
\end{warningbox}




\noindent This will have created a skeleton project in the /home/monitor/WinCC/SRTM\_SandBox directory. \\
    
\noindent\textbf{Step 2:} Copy a working project into the new project directory. For now the SRTM\_Monitor\_v4 works well.

\begin{lstlisting}
cd ~monitor/WinCC/SRTM_SandBox
cp -r  SRTM\_Monitor_v4 <Project Name>
cd NewProject
\end{lstlisting}

\noindent\textbf{Step 3:} Update config/config file
\begin{lstlisting}
sed -i 's/SRTM_Monitor_v4/<Project Name>/g' config/config
\end{lstlisting}

\noindent\textbf{Step 4:} Optional: Change pmonPort to avoid conflict
\begin{lstlisting}
sed -i 's/pmonPort = 4999/pmonPort = 5001/g' config/config
\end{lstlisting}

\noindent\textbf{Step 5:} Clear old log files
\begin{lstlisting}
rm -rf log/*
\end{lstlisting}

\noindent\textbf{Step 6:} Verify config/config
\begin{lstlisting}
cat config/config
\end{lstlisting}

\begin{center}
\begin{tabular}{|l|l|}
\hline
\rowcolor{tableheader}\textcolor{white}{\textbf{Setting}} & \textcolor{white}{\textbf{Value}} \\
\hline
proj\_path & \texttt{/home/monitor/WinCC/SRTM\_SandBox/<Project Name>} \\
\hline
pmonPort & 5001 (unique port) \\
\hline
distributed & 1 \\
\hline
\end{tabular}
\end{center}

\noindent\textbf{Step 7:} Stop the original project before starting\\

\noindent The copied project shares default port configurations with the original. You must stop the original project first:
\begin{lstlisting}
pkill -u $USER -f  <Project Name>'
# Verify processes stopped:
ps aux | grep -i wincc | grep -v grep
\end{lstlisting}

\noindent\textbf{Step 8:} Refresh the Project Administrator panel (started by startPA) — the new project should appear in the list. Start it. If you are asked for a password, just click "OK".

\begin{tipbox}
\textbf{Note:} If you need to run both projects simultaneously, add unique ports to config/config:\\
\texttt{dataPort = 4898}\\
\texttt{eventPort = 4899}\\
Otherwise, the default ports will conflict.
\end{tipbox}

\begin{tipbox}
\textbf{FYI:} To check settings from an existing project:\\
\texttt{cat ~/WinCC\_Projects/<ProjectName>/config/config}\\[0.3cm]
Old log files may contain references to the original project name — this is harmless. Use \texttt{grep -r 'OldName' . 2>/dev/null} to verify no critical files are affected.
\end{tipbox}

\noindent\textbf{Step 4:} Creating Datapoints\\
%==============================================================================

\noindent In WinCC datapoints are the data that are passed from the OpcUa server to WinCC. A datapoint element is a group of similar datapoints. For the SRTM the datapoint element is called SRTM. The datapoint element SRTM is part of a datapoint type called SRTMRegs. There are two ways to create datapoints: manually and using Cacophony. The latter method is preferred since it automatically generates all of the datapoints from the quasar project. Since there are over 100 datapoints, this is quite painful to do manually. \\

\noindent\textbf{Creating Datapoints with Cacophony} (preferred method)

\bigskip
\noindent Some useful information can be found here:
\begin{enumerate}
  \item See https://www.youtube.com/watch?v=g2LWOx1BufI at 13:40 or so
  \item See https://github.com/quasar-team/Cacophony
\end{enumerate}

\noindent Download the cacophony package and run it to create two scripts for defining the SRTM datapoints.
\begin{lstlisting}
  cd quasar-srtm-built (this is the top directory of the quasar project used to create the quasar OpcUa server)
  git clone https://github.com/quasar-team/Cacophony.git
  pip install colorama (this might be necessary if it is not already installed)
  python Cacophony/generateStuff.py --dpt_prefix SRTM --server_name SRTM --driver_number 10 --subscription SRTM_SUBSCRIPTIONS
  cd Cacophony/generated
  cp *.ctl ~/WinCC/SRTM_SandBox/<Project Name>/scripts/libs/
\end{lstlisting}

\noindent You should be able to see the files appear in Gedi under $<$Project Name$>$ $\to$ Libraries.
We will now create a panel that will allow us to run these scripts.

 \begin{lstlisting}
   Create a new panel using the first button in Gedi (looks like a page with a + sign)
   Add a pushbutton (about the middle of the first row of buttons)
   To change the name of the button, change the "Button Label" in the Property Editor window that should open when you click on the button in the panel.
   In the Script panel (Part of the Property Editor) click on the script button next to the Clicked event (looks like "{..})"
     Add the line: #uses "createDpts.ctl" at the top of the script
     Add the line: createDpts();
       as part of the main(..) body (i.e. between the curly braces)
   Save and run this panel (choose a name to save the file such as CreateDPTs.pnl)
   In the QuickTest window, click on the button. You should see an entry in the log file that says "creating DPTs for class Regs"
   If you open the Para window (six button on the top row), you should now see a DPT type called SRTMRegs.
\end{lstlisting}

\noindent Add another pushbutton to the same panel (I used the Button Label "Parse Config")
\begin{lstlisting}
   In the Script panel click on the script button next to Clicked event
   At the top add: #uses "configParser.ctl"
      In the body of the script add: 
      parseConfig( "/home/monitor/quasar-srtm-built/build/bin/config.xml",
      true,
      true,
      true);
   Save the script and run the panel with QuickTest
\end{lstlisting}

\noindent You should see a new window pop up with the added button displayed.
\begin{lstlisting}
  Click on the Parse Config button (you should see some messages in the log panel)
  This should produce a set of DPs that list all of the variables available from the SRTM (Open a Para window and scroll down until you see the datapoint type SRTMRegs)
\end{lstlisting} 
  You can skip to the next section

\begin{lstlisting}
  Open a Para window (if you don't already have one open)

\begin{lstlisting}

    Right click on your newly created datapoint
    Choose Insert config --> Periphery address
    Click on the _address config, choose the OPCUA Client Driver type and click Configure
    Choose the Server SRTM

    Click on "Get Item" and choose from the variables from the in the drop down menu
    Select the "Input" Direction
    Click on the "Address active" button and hit "OK"

\subsection{Adding an LCD Number Display}

\begin{enumerate}
    \item \textbf{Objects → More Objects → LCD Number}
    \item Draw the LCD area on the panel
    \item Select the LCD widget, then in Property Editor find \textbf{Event → Initialize}
    \item Click the script button to open the Script Editor
    \item Enter the following Initialize script:
\end{enumerate}

\textbf{LCD Initialize Script:}
\begin{lstlisting}
main()
{
  dpConnect("updateLCD", "dist_1:SRTM_FPGA_temp.:_online.._value");
}

void updateLCD(string dp, float value)
{
  this.value = value;
}
\end{lstlisting}

\begin{enumerate}
    \setcounter{enumi}{5}
    \item Save the script (File → Save) and close the Script Editor
\end{enumerate}

\begin{tipbox}
\textbf{Note:} Each widget requires a datapoint binding or script to display live data. Double-clicking a widget opens its configuration. The Script Editor (shown when clicking script icons) allows custom control logic using the \texttt{dpConnect} function.
\end{tipbox}
